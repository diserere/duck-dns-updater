# duck-dns-updater

Небольшой Bash-скрипт для обновления динамических DNS-записей на [DuckDNS](https://www.duckdns.org/).

## Настройка

Нужны Bash, `curl` и `column` (последняя команда используется для отображения журнала). Скопируйте пример конфигурации и укажите свои домены и токен DuckDNS:

```bash
cp .env.example .env
```

Отредактируйте `.env`. Переменная `DOMAINS` содержит имена доменов через запятую, `TOKEN` — токен DuckDNS, `TZ` — необязательный часовой пояс для отметок времени, `IP` — необязательный IP-адрес. Если `TZ` не задана, используется локальная часовая зона хоста. Для постоянного переопределения добавьте, например, `TZ="Europe/Moscow"` в `.env`; `-tz` переопределяет зону только для одного запуска. Пустой `IP` позволяет DuckDNS определить адрес запроса. Файл `.env` загружается Bash-командой `source`, поэтому используйте только созданный и проверенный вами файл.

Не добавляйте `.env` в Git: в нём находятся персональные настройки и токен.

## Запуск

```bash
./duck-dns-updater
```

Чтобы получить строку cronjob с абсолютным путём к скрипту, выполните:

```bash
./duck-dns-updater --print-cronjob
```

Команда выведет расписание каждые пять минут. Скопируйте строку в crontab командой `crontab -e`; скрипт сам не меняет crontab.

Журнал при запуске с `--journal` сохраняется в `logs/`. Имя файла зависит от имени скрипта, например `logs/duck-dns-updater.log`. Каталог создаётся при первой записи и исключён из Git.

```cron
*/5 * * * * /абсолютный/путь/к/duck-dns-updater --journal --updates-only >/dev/null 2>&1
```

## Аргументы

Флаги можно указывать в любом порядке. Короткие и длинные формы равнозначны:

| Аргумент | Действие |
| --- | --- |
| `-p`, `--print-cronjob` | Вывести готовую cron-строку с расписанием раз в пять минут. |
| `-V`, `--version` | Показать версию в формате `vX.Y.Z` и завершиться до загрузки `.env` и сетевого запроса. |
| `-tz ЗОНА`, `--timezone ЗОНА` | Задать часовую зону отметки времени. |
| `-v`, `--verbose` | Запросить подробный ответ DuckDNS. |
| `-j`, `--journal` | Добавлять результаты в `logs/<имя-скрипта>.log`. |
| `-u`, `--updates-only` | Автоматически запросить подробный ответ и не выводить `NOCHANGE` в консоль или журнал. |
| `-l`, `--list-journal` | Показать журнал. |
| `-R`, `--reset-journal` | Очистить журнал, оставив файл на месте. |
| `-h`, `--help` | Показать справку по режимам и флагам. |

Режимы `--help`, `--version`, `--print-cronjob`, `--list-journal` и `--reset-journal` запускаются отдельно и не сочетаются с другими флагами. Неизвестные флаги, лишние значения и отсутствие значения у `--timezone` считаются ошибкой. Старые флаги `-d` и `--print-cron` удалены.

Примеры:

```bash
./duck-dns-updater --verbose
./duck-dns-updater --journal --updates-only
./duck-dns-updater --timezone Europe/Moscow --verbose
./duck-dns-updater --list-journal
./duck-dns-updater --reset-journal
./duck-dns-updater --help
./duck-dns-updater --version
```

## Версия и релизы

Номер версии в формате SemVer хранится без префикса в константе `VERSION`; `-V` / `--version` и Git-тег выводят его с префиксом `v`. Первая версия — `0.1.0`, её отображение и тег — `v0.1.0`. Git-теги выпусков создаются вручную на коммите релиза и называются `vX.Y.Z`.

До `1.0.0` исправления без изменения интерфейса повышают PATCH, а новые возможности и несовместимые изменения интерфейса — MINOR. Начиная с `1.0.0`, несовместимые изменения повышают MAJOR, новые возможности — MINOR, исправления — PATCH.
