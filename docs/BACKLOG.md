# Бэклог

Список объединяет задачи из исходного скрипта и предложения по итогам обзора. Первый этап ограничен удобством развёртывания текущей версии; риски её текущей обработки сетевых и HTTP-ошибок приняты для первого запуска на хостингах.

## P0 — минимальный набор для первого развёртывания

- [x] **Использовать часовую зону хоста по умолчанию.** Если `TZ` отсутствует или пуста, получать отметку времени в локальной зоне хоста; поддержать постоянное переопределение через `.env` и разовое через `-tz`.
- [x] **Печатать готовую строку cron.** Флаги `--print-cron` и `-p` выводят расписание каждые пять минут и команду с абсолютным путём к скрипту с флагами `-v -d -u`; `-u` исключает ответы `NOCHANGE` из журнала, crontab автоматически не меняется.
- [x] **Хранить журнал в `logs/`.** Имя остаётся динамическим и основано на имени скрипта; каталог фиксирован, создаётся при записи/очистке и целиком исключён из Git.
- [x] **Заключить переменные и пути в кавычки.** Исправлены пути к скрипту, `.env` и журналу, URL-запроса, а также вывод/добавление строк журнала.
- [ ] **Уточнить загрузку `.env`.** На первый этап оставить подключение как Bash-конфига, заключив путь в кавычки и документировав, что файл должен быть доверенным. Отдельно решить, нужен ли allowlist-парсер, который читает только `DOMAINS`, `TOKEN`, `TZ`, `IP` и не исполняет файл.

## P1 — надёжность и диагностика

- [ ] **Разделить ошибки транспорта, HTTP и DuckDNS.** Сохранять код завершения `curl` как признак сетевой/прокси-ошибки; отдельно получать HTTP-статус; распознавать прикладной ответ DuckDNS (`OK`, `KO`, `NOCHANGE`). Ошибку `curl` нельзя терять при добавлении HTTP-обработки.
- [ ] **Обрабатывать HTTP-ошибки, включая 502 и 503.** Сейчас `curl` без `--fail` может завершиться с кодом `0`, даже когда сервер вернул страницу ошибки; такие ответы попадают в журнал как будто это обычный ответ. При HTTP 200 сохранять тело ответа; для других статусов записывать диагностический статус и полезную информацию без длинных HTML-страниц.
- [ ] **Ограничить время запроса и защититься от параллельных запусков.** Долгий запрос может зависнуть и пересечься со следующим запуском cron. Определить разумный таймаут и способ не допускать одновременной записи/обновления.

## P2 — удобство и дальнейшая уборка

- [ ] **Разбирать аргументы независимо от порядка.** Сейчас опции проверяются последовательно и ожидаются в фиксированном порядке; `-l` и `-R` обрабатываются только как первый аргумент. Поддержать сочетание флагов и понятные сообщения для неизвестных или неполных параметров.
- [ ] **Добавить автоматизированные проверки ключевых сценариев.** Проверить обработку аргументов, кодов `curl`/HTTP и ответов DuckDNS без реальных сетевых запросов. Детали набора проверок определить при реализации соответствующих пунктов.

## Принятые уточнения

- Код ошибки самого `curl` нужен для диагностики инфраструктуры (например, недоступной сети или прокси) и должен сохраняться независимо от HTTP-статуса.
- Первичный обзор выявил, что текущий код логирует код завершения `curl`, но не получает HTTP-статус; из-за этого HTTP 502/503 неотличимы от обычного ответа по коду возврата.
- Порядок аргументов сейчас фиксирован намеренно как упрощение первой версии; возможность сделать полноценный парсер — кандидат на доработку, а не дефект, который нужно менять в рамках стартового снимка.
- Пользователь принимает риски текущей обработки сетевых и HTTP-ошибок ради быстрого первого развёртывания; обработка ошибок остаётся следующим приоритетом после минимального набора.
